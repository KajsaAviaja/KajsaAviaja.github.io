# Hvad Består en Hjemmeside af

En hjemmeside er bygget op af flere lag, der arbejder sammen. I bund og grund består det af

- **HTML** (HyperText Markup Language) er hjemmesidens struktur. Det er her indholdet defineres, altså overskrifter, tekst, billeder, knapper og links.
- **CSS** (Cascading Style Sheets) styrer, hvordan hjemmesiden ser ud, altså farver, skrifttyper, afstand og layout.
- **JavaScript** gør hjemmesiden interaktiv. Det gør det muligt for siden at reagere på brugerens handlinger og styre logikken bag funktionaliteten.

I dette projekt bruger vi en samling af moderne værktøjer til at håndtere hvert af disse lag.

# Vores techstack

Til at bygge dette webspil bruger vi et techstack bestående af følgende værktøjer, som hver især løser en specifik del af opgaven.

## Typescript

TypeScript er et sprog, der bygger ovenpå JavaScript og tilføjer typer. Det betyder, at fejl som f.eks. forkerte datatyper opdages allerede mens vi skriver koden, i stedet for først når spillet kører.

## Vite

Vite er et byggeværktøj, der gør det hurtigt at udvikle og bygge hjemmesiden. Det sørger for, at ændringer i koden vises med det samme i browseren, mens vi udvikler.

## React

React er et JavaScript-bibliotek til at bygge brugergrænseflader. Det gør det muligt at opbygge siden af genbrugelige komponenter, der styrer deres eget indhold og opførsel.

## Tailwind

Tailwind er et CSS-framework, der bruges til at style hjemmesiden. I stedet for at skrive CSS i separate filer, tilføjer vi klasser direkte i HTML/JSX, som styrer udseendet.

## React Router

React Router håndterer navigation i webspillet. Det gør det muligt at skifte mellem forskellige sider og views uden at genindlæse hele siden.

## JSON

JSON (JavaScript Object Notation) er et format til at strukturere data. Vi bruger det til at gemme og indlæse indhold som f.eks. spillets tekster og valg, så det er let at læse og ændre.

## Git

Git er et versionsstyringssystem, som vi bruger til at holde styr på ændringer i koden. Det gør det muligt at gemme forskellige versioner af projektet, arbejde sammen uden at overskrive hinandens arbejde og gå tilbage til tidligere versioner, hvis noget går galt.
